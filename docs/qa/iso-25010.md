# RZL — ISO/IEC 25010:2023 Quality Instrument

Evaluated by **5 IT professionals**. Results feed Chapter 4.

> ⚠️ **Confirm the revision with your adviser before printing.** ISO/IEC 25010 was revised
> in **2023**. The 2011 model had 8 characteristics; the 2023 model has **9** and renamed
> two of them. Many capstone templates still circulate the 2011 names. If Chapter 3 cites
> `25010:2023` while the questionnaire uses 2011 sub-characteristics, that inconsistency is
> an easy panel catch.

## 1. What changed between 2011 and 2023

| 2011 | 2023 | Change |
|---|---|---|
| Functional Suitability | Functional Suitability | unchanged |
| Performance Efficiency | Performance Efficiency | unchanged |
| Compatibility | Compatibility | unchanged |
| Usability | **Interaction Capability** | renamed; sub-characteristics reworked (includes *Inclusivity*, *Self-descriptiveness*) |
| Reliability | Reliability | unchanged (sub-characteristics adjusted) |
| Security | Security | unchanged |
| Maintainability | Maintainability | unchanged |
| Portability | **Flexibility** | renamed; *Adaptability*, *Scalability*, *Installability*, *Replaceability* |
| — | **Safety** | new characteristic |

**Decision needed:** either use the 2023 model as printed below (defensible, current), or
use 2011 and say so explicitly in Chapter 3. Do not mix. Record the choice in
`docs/spec/decisions.md`.

## 2. Evaluation scale

5-point Likert:

| Score | Interpretation |
|---|---|
| 5 | Fully implemented / Excellent |
| 4 | Implemented with minor gaps / Very Good |
| 3 | Partially implemented / Good |
| 2 | Weakly implemented / Fair |
| 1 | Not implemented / Poor |

Interpretation bands for the weighted mean:

| Mean range | Verbal interpretation |
|---|---|
| 4.21 – 5.00 | Fully Implemented |
| 3.41 – 4.20 | Implemented |
| 2.61 – 3.40 | Partially Implemented |
| 1.81 – 2.60 | Poorly Implemented |
| 1.00 – 1.80 | Not Implemented |

These bands are the standard ones used in Philippine capstone papers. State the formula:

```
weighted mean = Σ(f × x) / N
```

where `f` = frequency of respondents choosing a score and `x` = the score value.

## 3. The instrument (2023 model)

25 items across 9 characteristics. Every item is phrased positively and maps to a
verifiable test case, so a respondent can be shown the evidence.

### Functional Suitability (FR-01 … FR-34)

| # | Item | Related TCs |
|---|---|---|
| 1 | The app provides the event information needed to plan attendance. | TC-001, TC-012 |
| 2 | The event search and filters return accurate results. | TC-005 … TC-015 |
| 3 | The admin functions correctly create, update, and archive events. | TC-063 … TC-069 |

### Performance Efficiency

| # | Item | Related TCs |
|---|---|---|
| 4 | The event feed loads within an acceptable time on a typical connection. | TC-001, TC-083 |
| 5 | Images and lists scroll smoothly without visible lag. | TC-083 |
| 6 | The app remains responsive when several features are used in sequence. | TC-080 |

### Compatibility

| # | Item | Related TCs |
|---|---|---|
| 7 | The app works consistently across different Android devices and versions. | TC-083, TC-084 |
| 8 | Calendar export and map navigation integrate correctly with other apps. | TC-031, TC-061 |

### Interaction Capability *(replaces Usability)*

| # | Item | Related TCs |
|---|---|---|
| 9 | A first-time user can find and open an event without instruction. | TC-001, TC-012 |
| 10 | Labels, icons, and navigation are self-descriptive. | TC-012 |
| 11 | The interface is usable by residents of different ages and digital literacy. | TC-046, TC-048 |
| 12 | Dark mode is readable and consistently applied. | TC-046 … TC-048 |

### Reliability

| # | Item | Related TCs |
|---|---|---|
| 13 | The app handles poor or lost connectivity without crashing. | TC-079, TC-080 |
| 14 | Data such as bookmarks and RSVPs persists reliably. | TC-028, TC-033 |
| 15 | Errors are presented clearly and the user can recover. | TC-081, TC-082 |

### Security

| # | Item | Related TCs |
|---|---|---|
| 16 | Guest users cannot perform actions that require an account. | TC-078 |
| 17 | Users can only modify their own content and profile. | TC-027, TC-076 |
| 18 | Administrative functions are inaccessible to ordinary users. | TC-077, TC-078 |

### Maintainability

| # | Item | Related TCs |
|---|---|---|
| 19 | The codebase is organised so features can be modified independently. | — (repo review) |
| 20 | The system can be updated without disrupting existing data. | — (migration review) |

### Flexibility *(replaces Portability)*

| # | Item | Related TCs |
|---|---|---|
| 21 | The app installs and runs on the devices available to the study. | TC-083 |
| 22 | The design extends to additional municipalities without redesign. | — (schema review) |

### Safety *(new in 2023)*

| # | Item | Related TCs |
|---|---|---|
| 23 | The app does not expose users to misleading event information without indicating the source. | TC-012 |
| 24 | User-generated content can be moderated to prevent harmful posts. | TC-076 |
| 25 | The app protects user data from unintended disclosure. | TC-027, TC-078 |

## 6. Common panel objections — prepare answers

| Objection | Answer |
|---|---|
| "n = 5 is not statistically valid." | Descriptive evaluation, not inferential. Criterion-referenced per ISO 25010; n is typical of software quality assessment studies and the limitation is stated in Chapter 5. |
| "These are your classmates." | Not the case — respondents are IT professionals outside the development team, and profiles are reported in §4. |
| "Why not 25010:2011?" | Whichever you chose, state it in Chapter 3 with the citation and be consistent throughout. |
| "How do you know it's secure?" | Point at TC-077/TC-078 and the RLS verification checklist, not at the rating. |
